# Тропа — клиент VLESS / VMess / Trojan для Windows

Свой аналог v2rayN для друзей из России. Владелец проекта общается на русском, документация и интерфейс на русском, код и идентификаторы на английском.

## Порядок чтения (для нового сеанса)

1. Этот файл.
2. `docs/08-roadmap.md` — что уже сделано и что делать дальше. **После каждого законченного шага ставь галочку и дописывай заметку.**
3. `docs/02-security.md` — **главный приоритет проекта**. Любое решение сначала проверяется по нему.
4. Остальное по мере надобности:
   - `docs/01-overview.md` — цели, пользователи, что не делаем;
   - `docs/03-architecture.md` — процессы, проекты решения, IPC, хранение;
   - `docs/04-domain-model.md` — модель профиля, форматы ссылок и подписок, правила совместимости;
   - `docs/05-config-generation.md` — как настройки превращаются в конфиги sing-box и Xray;
   - `docs/06-features.md` — экраны и функции, полный список настроек и зависимостей;
   - `docs/07-testing-diagnostics.md` — алгоритмы тестов серверов и диагностики;
   - `docs/09-decisions.md` — журнал принятых решений (ADR). Новые решения дописывать туда;
   - `docs/10-release.md` — ключ подписи, выпуск, манифест, ручной чек-лист.
5. `docs/info.ru.json` — тексты справки для кнопок «i» (105 статей). Это ресурс приложения, не только документация.

## Неизменные правила

1. **Безопасность данных пользователя важнее обхода блокировок, обход важнее всего остального.**
2. Никаких zapret, GoodbyeDPI, WinDivert и других сторонних драйверов и утилит обхода DPI. Их *приёмы* (фрагментация, шум) реализуются только встроенными средствами ядер sing-box и Xray.
3. Любой исполняемый файл третьей стороны (ядра, wintun.dll) запускается только после проверки SHA-256 по хэшу, зашитому в нашу сборку или в наш подписанный манифест обновлений. Обновление «последней версии с GitHub» без проверки запрещено.
4. Сторонний контент (подписки, ссылки, импортируемые JSON, шаблоны) — недоверенные данные. Никогда не передаём ядру чужой конфиг как есть: только через нашу модель и наш генератор.
5. Каждое изменение системы (прокси Windows, реестр, брандмауэр, loopback-исключения) записывается в журнал изменений и откатывается при выходе, сбое и удалении.
6. Ничего не удаляем вне своих каталогов. Запись файлов только атомарно (временный файл → rename) с резервной копией настроек.
7. Ни телеметрии, ни автоматической отправки чего-либо. Отчёт диагностики уходит только руками пользователя.
8. Секреты (UUID, пароли, ключи, URL подписок) не попадают в логи, отчёты, скриншоты окна ошибок и буфер обмена без явного действия.

## Стек

- .NET 10 (LTS, SDK закреплён в `global.json`), C#, Avalonia 12 + CommunityToolkit.Mvvm, xUnit v3.
- Ядра: sing-box (основное) и Xray (для XHTTP и функций, которых нет в sing-box). Версии и хэши — `tools/cores.lock.json`.
- Установщик: Inno Setup. CI: GitHub Actions.
## Команды

```bash
powershell -ExecutionPolicy Bypass -File tools/fetch-cores.ps1   # ядра по lock-файлу с проверкой хэшей
powershell -ExecutionPolicy Bypass -File tools/fetch-geo.ps1     # наборы правил .srs по lock-файлу
dotnet build Tropa.slnx
dotnet test Tropa.slnx
powershell -ExecutionPolicy Bypass -File tools/build-release.ps1   # выпуск: out\publish, установщик (если есть Inno Setup 6), SHA256SUMS
dotnet run --project tools/Tropa.Release -- <keygen|manifest|sign|verify>   # манифест обновлений, см. docs/10-release.md
```

Новая версия ядра: прочитать changelog, затем `tools/update-cores-lock.ps1 -SingBox X -Xray Y`, проверить diff lock-файла, прогнать тесты.

Скрипты `.ps1` хранятся в UTF-8 с BOM, иначе Windows PowerShell 5.1 ломает кириллицу.

**Ловушки инструментов:** в bash-heredoc этой среды `
` и `	` превращаются в настоящие перевод строки и табуляцию — файлы с обратными слешами (csproj, C#-строки) писать через Write/Edit, а не через heredoc/sed.

**Запуск интерфейса для проверки (ВАЖНО: у владельца может быть запущена установленная Тропа — автоматизацию направлять только на PID своего процесса):** `TROPA_DATA_DIR=<временная папка> src/Tropa.App/bin/Debug/net10.0-windows/Tropa.exe` (только Debug) — не трогает настоящий профиль. Не нажимать «Подключить» без согласия владельца: это меняет прокси Windows.

## Структура репозитория (целевая)

```
tropa/
  CLAUDE.md
  docs/                 спецификация
  design/canvas-src/    исходники макетов
  src/
    Tropa.Core/         модель, парсеры, правила совместимости, генераторы конфигов (без IO)
    Tropa.Infrastructure/ хранилище, DPAPI, загрузка подписок, обновления, проверка подписей
    Tropa.Ipc/          контракты сообщений App ↔ Service
    Tropa.Service/      служба Windows: ядра, TUN, системные изменения, тесты
    Tropa.App/          интерфейс Avalonia, трей
  tests/
    Tropa.Core.Tests/
    Tropa.Integration.Tests/
  tools/                скрипты: загрузка и проверка ядер, подпись манифеста
  installer/            Inno Setup
```

## Соглашения

- Логика совместимости опций живёт в одном месте (`Tropa.Core/Compatibility`) и используется и интерфейсом, и валидатором перед запуском ядра.
- Генераторы конфигов покрыты golden-тестами (эталонные JSON в `tests/Tropa.Core.Tests/Golden/`).
- Любой новый пункт настроек = запись в модели + правило совместимости (если есть) + статья в `info.ru.json` + строка в `docs/06-features.md`.
