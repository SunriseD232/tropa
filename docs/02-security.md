# 02. Безопасность — главный приоритет

Любая функция сначала проверяется по этому документу. При конфликте «безопаснее» против «обходит лучше» выигрывает «безопаснее», а компромисс записывается в `09-decisions.md`.

## 1. Что защищаем

| Актив | Пример | Чем грозит утечка |
|---|---|---|
| Файлы и данные пользователя на диске | документы, фото | потеря данных, вредонос |
| Секреты подписок | URL подписки, UUID, пароли Trojan, ключи Reality | чужой пользуется подпиской; провайдер блокирует |
| История посещений | DNS-запросы, домены в логах | приватность, риск для пользователя в РФ |
| Целостность системы | прокси Windows, брандмауэр, реестр | «после удаления программы пропал интернет» |

## 2. Модель угроз

1. **Цепочка поставок.** Обновление стороннего компонента приносит вредонос. Именно поэтому отказались от zapret. Ядра sing-box, Xray и wintun.dll — тоже сторонние бинарники, к ним те же требования.
2. **Вредоносная подписка или ссылка.** Провайдер или злоумышленник подсовывает данные, которые ломают парсер, пишут файлы, открывают порты наружу или уводят трафик.
3. **Локальные программы.** Другая программа пользуется открытым портом прокси или подключается к именованному каналу службы, чтобы повысить права.
4. **Посредник в сети.** Подмена сертификата (allowInsecure), подмена DNS, подмена обновлений.
5. **Сбой самой Тропы.** Падение оставляет систему в изменённом состоянии.

## 3. Требования

### 3.1. Сторонние бинарники (ядра, wintun)
- Версии ядер **закреплены**. Хэши SHA-256 лежат в `tools/cores.lock.json` и вшиваются в сборку.
- Обновление ядер — только через **наш манифест**, подписанный ECDSA P-256 (ADR-023; изначально планировался Ed25519). Публичный ключ вшит в приложение, приватный хранится вне репозитория (секрет CI или офлайн). Манифест содержит версию, URL и SHA-256 каждого файла.
- Перед **каждым** запуском ядра служба сверяет хэш файла с ожидаемым. Не совпало — ядро не запускается, пользователю объясняется почему.
- Бинарники лежат в `%ProgramFiles%\Tropa\cores\`: писать туда может только администратор.
- Никаких драйверов, кроме wintun (подписан WireGuard LLC, хэш закреплён).
- Новую версию ядра сначала проверяет владелец (changelog, прогон интеграционных тестов) и только потом добавляет в манифест.

### 3.2. Недоверенный ввод
- Подписка: только HTTPS (HTTP — с явным предупреждением и подтверждением). Размер ответа ≤ 5 МБ, таймаут 20 с, ≤ 5 редиректов, без перехода на file:// и другие схемы.
- Парсеры ссылок и подписок толерантны к мусору, но строги к значениям. Порт 1–65535, адрес — домен или IP, UUID — формат UUID, пути без управляющих символов. Названия очищаются от управляющих и bidi-символов (RLO и т. п.) и обрезаются до 64 символов.
- Импорт JSON-конфигов sing-box/Xray: **извлекаются только outbound-ы** в нашу модель. Inbound-ы, log.output, experimental, api, controller и пути к файлам игнорируются.
- «Свой шаблон» в экспертных настройках сливается через **белый список** путей. Запрещены пути к файлам (`log.output`, `cache_file.path` вне нашего каталога), inbound-ы с listen ≠ loopback, `clash_api.external_controller` вне loopback, любые `exec`-подобные поля. Нарушение — шаблон отклоняется с пояснением.
- Гео-базы — данные, а не код, но тоже проверяются: хэш из sha256-файла источника, размер, формат (ядро должно их прочитать в тестовом запуске до замены рабочих).

### 3.3. Разделение привилегий
- **Tropa.App** работает с правами пользователя (`asInvoker`). Права администратора у интерфейса никогда не запрашиваются.
- **Tropa.Service** — служба Windows (LocalSystem). Она создаёт TUN, запускает ядра, меняет системные настройки. Принимает только типизированные команды из `Tropa.Ipc`, никогда не принимает пути к исполняемым файлам или произвольные аргументы командной строки.
- IPC — именованный канал с ACL: только SYSTEM и SID пользователя активной интерактивной сессии. При подключении служба проверяет SID клиента и путь его процесса (`%ProgramFiles%\Tropa\Tropa.App.exe`, подпись при наличии).
- Ядра запускаются в Job Object (убиваются вместе со службой) и слушают только loopback.

### 3.4. Секреты
- Хранятся отдельно от настроек: `%APPDATA%\Tropa\secrets.bin`, шифрование DPAPI (CurrentUser).
- В службу конфиг ядра передаётся по IPC в памяти. Служба записывает его в `%ProgramData%\Tropa\run\` (ACL: только SYSTEM), запускает ядро и удаляет файл, как только ядро сообщило о старте. Если ядро умеет читать конфиг из stdin, используется stdin.
- Логи и отчёты проходят через `SecretScrubber`: UUID, пароли, pbk/sid, URL подписок, `vless://`/`vmess://`/`trojan://` заменяются масками.
- Уровень журнала по умолчанию `warning`. `debug` автоматически выключается через 30 минут.
- Копирование ссылки сервера — только по явной кнопке. Буфер обмена очищается через 60 секунд, если в нём всё ещё наша ссылка.

### 3.5. Локальные порты
- SOCKS/HTTP слушают 127.0.0.1. Авторизация включена по умолчанию (случайные логин и пароль, генерируются при установке).
- Опция «случайные порты» (по умолчанию выключена, но доступна): фиксированный 10808 легко найти сканированием.
- Разрешение подключений из LAN принудительно включает пароль (правило совместимости).
- API статистики ядер (clash_api, Xray API) — только loopback, случайный порт, случайный секрет.

### 3.6. Целостность системы: журнал изменений
- `SystemChangeJournal` — до любого изменения записывает исходное значение (атомарно, с fsync) в `%ProgramData%\Tropa\journal.json` (для служебных изменений) или `%LOCALAPPDATA%\Tropa\journal.json` (для пользовательских, например системного прокси).
- Что журналируется: системный прокси (HKCU, делает App), Smart Multi-Homed Name Resolution (HKLM-политика, делает служба), loopback-исключения AppContainer (служба; откатываются только добавленные нами). Фильтры WFP kill switch в журнал не пишутся: они живут в динамическом сеансе и исчезают вместе со службой (ADR-021), запись автозапуска (App).
- Откат: при штатном отключении, при старте после сбоя (журнал не пуст → откатить, потом работать), при удалении (деинсталлятор вызывает `Tropa.Service --rollback-all`).
- В трее и меню «Пуск» есть пункт «Аварийно вернуть настройки сети», который работает даже при сломанной конфигурации.

### 3.7. Файлы пользователя
- Тропа пишет только в свои каталоги: `%APPDATA%\Tropa`, `%LOCALAPPDATA%\Tropa`, `%ProgramData%\Tropa`, `%ProgramFiles%\Tropa`.
- Удаляет только свои файлы по явному списку, без рекурсивного удаления по маске вне своих каталогов.
- Запись настроек атомарная (temp → `File.Replace`), хранится 5 последних резервных копий. Миграции схемы версионированы, перед миграцией создаётся копия.
- Импорт и экспорт работают только с файлом, который пользователь выбрал в диалоге.

### 3.8. Сеть и обновления
- Обновления приложения — подписанный манифест (тот же ключ) плюс подпись Authenticode установщика, если появится сертификат (вариант для OSS — SignPath).
- Автоматической установки нет: только уведомление и кнопка.
- allowInsecure: сервер подсвечивается, в авто-выбор не попадает без подтверждения.
- Телеметрии нет. Сетевые запросы самой Тропы (не ядра): подписки, наш манифест, гео-базы, тестовые адреса. Список закрытый и описан в настройках.

### 3.9. Сборка и релиз
- Сборка в GitHub Actions из тега, детерминированная (`Deterministic`, `ContinuousIntegrationBuild`). Для зависимостей NuGet включён lock-файл (`RestorePackagesWithLockFile`).
- Минимум NuGet-зависимостей, каждая новая записывается в `09-decisions.md` с обоснованием.
- В релиз прикладываются SHA-256 артефактов.

## 4. Чек-лист перед мерджем любой функции

- [ ] Не появилось нового стороннего исполняемого кода без закреплённого хэша.
- [ ] Ввод извне валидируется, лимиты размеров есть.
- [ ] Секреты не попадают в логи (есть тест на `SecretScrubber`, если появился новый тип секрета).
- [ ] Системные изменения идут через `SystemChangeJournal`, откат проверен.
- [ ] Ничего не пишется и не удаляется вне своих каталогов.
- [ ] Новые порты слушают только loopback.
