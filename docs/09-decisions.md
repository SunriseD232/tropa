# 09. Журнал решений (ADR)

Формат: номер, дата, решение, почему, последствия. Новые решения — в конец.

## ADR-001 · 2026-10-07 · Безопасность данных — приоритет №1
**Решение:** при конфликте «безопаснее» против «лучше обходит» выбираем безопасность. **Почему:** требование владельца. Друзья доверяют программе компьютер и данные. **Последствия:** `02-security.md` обязателен к исполнению, у каждого PR есть чек-лист.

## ADR-002 · 2026-10-07 · Без zapret, GoodbyeDPI, WinDivert
**Решение:** не встраивать и не запускать сторонние утилиты и драйверы обхода DPI. Приёмы (фрагментация, шум) реализуем только опциями ядер sing-box/Xray. **Почему:** риск вредоноса в обновлениях, драйвер ядра с полным доступом к трафику, риск потери данных. **Последствия:** фрагментация работает только для трафика, проходящего через ядро (режим TUN или прокси), а не для всей системы на уровне драйвера.

## ADR-003 · 2026-10-07 · Ядра тоже под контролем цепочки поставок
**Решение:** закреплённые версии и SHA-256, обновление только через наш подписанный Ed25519 манифест, проверка хэша перед каждым запуском. **Почему:** ядра — такой же сторонний код, как zapret. **Последствия:** новые версии ядер появляются у пользователей после проверки владельцем, а не сразу.

## ADR-004 · 2026-10-07 · Стек: .NET 10 + Avalonia 11
**Решение:** C#/.NET 10 LTS, Avalonia (11 → обновлено до 12, см. ADR-010), CommunityToolkit.Mvvm, xUnit, Inno Setup. **Почему:** нативная работа со службами Windows, DPAPI, WFP, реестром. Avalonia даёт современный UI, встроенный трей и возможность портирования. **Альтернативы:** WPF (только Windows, устаревший вид), Tauri (сложнее работа с привилегиями и службой).

## ADR-005 · 2026-10-07 · Разделение на App (пользователь) и Service (SYSTEM)
**Решение:** привилегированные операции — только в службе Windows. Интерфейс без прав администратора. Автозапуск интерфейса через HKCU Run. **Почему:** минимальная привилегированная поверхность, нет UAC при каждом входе. **Последствия:** тексты `autostart` в `info.ru.json` и в исходниках макета исправлены (2026-10-07); холст обновится при следующей публикации.

## ADR-006 · 2026-10-07 · Конфиг ядра генерирует App, служба его проверяет
**Решение:** генерация в App (там доступны секреты DPAPI CurrentUser), повторная проверка `ConfigGuard` в службе. **Почему:** секреты не хранятся под SYSTEM, а служба не доверяет клиенту.

## ADR-007 · 2026-10-07 · sing-box основное ядро, Xray по требованию
**Решение:** sing-box всегда фронт (TUN, DNS, правила по процессам). Xray запускается за SOCKS только для XHTTP и Xray-only функций. **Почему:** у sing-box лучше TUN и правила по процессам, у Xray новинки протокола. **Последствия:** UDP для гибридных профилей идёт через SOCKS5 UDP ASSOCIATE, его надо проверить интеграционными тестами.

## ADR-008 · 2026-10-07 · Сторонние конфиги не исполняются
**Решение:** из импортируемых JSON берём только outbound-ы. Пользовательский шаблон сливается по белому списку. **Почему:** чужой конфиг может писать файлы (`log.output`), открывать порты наружу, уводить трафик.

## ADR-009 · 2026-10-07 · Нет своей серверной части
**Решение:** клиент работает со сторонними подписками. Важна совместимость: User-Agent, HWID, разные форматы ответа. **Почему:** друзья используют чужие подписки.

## ADR-010 · 2026-10-07 · Актуальные версии на старте
**Решение:** Avalonia 12.1.3 (а не 11, как в первой версии ADR-004), CommunityToolkit.Mvvm 8.4.2, xUnit v3 3.2.2 (стабильная линия 3.x вместо свежей 4.0), Microsoft.Extensions.Hosting.WindowsServices 10.0.12. Ядра: sing-box 1.14.2, Xray 26.9.30. **Почему:** последние стабильные версии на дату старта. **Последствия:** примеры конфигов в `05-config-generation.md` писались для sing-box 1.12. Каждый блок генератора сверяется со схемой 1.14 и фиксируется golden-тестом.

## ADR-011 · 2026-10-07 · Лицензии ядер
**Решение:** sing-box — GPL-3.0-or-later, Xray — MPL-2.0. Распространяем их неизменёнными бинарниками отдельными процессами. В установщик кладём тексты лицензий и ссылки на исходники точных версий (тег из lock-файла). **Почему:** требования GPL/MPL при распространении бинарников. **Последствия:** своё приложение не линкуется с ядрами и общается с ними только через конфиги и процессы.

## ADR-012 · 2026-10-07 · CI закреплён по хэшам
**Решение:** GitHub Actions подключаются по SHA коммита (`actions/checkout` v7.0.1, `actions/setup-dotnet` v6.0.0), у токена только `contents: read`, restore в `--locked-mode`. **Почему:** тег action можно перевесить на вредоносный коммит. Это та же угроза цепочки поставок, что и с ядрами.

## ADR-013 · 2026-10-07 · Отдельный порт для локальной сети
**Решение:** локальный mixed-порт всегда слушает только 127.0.0.1. В режиме «Только браузеры» он без пароля: системный прокси Windows не умеет передавать учётные данные, и браузеры показывали бы окно ввода пароля. Доступ из LAN — отдельный inbound `lan-in` на `LanPort` (10809), пароль на нём обязателен всегда. **Почему:** нельзя одновременно иметь системный прокси без запроса пароля и защищённый порт, открытый в сеть. **Последствия:** правило совместимости «LAN → пароль на локальном порту» заменено на «Только браузеры → без пароля на локальном порту»; `ConfigGuard` пропускает 0.0.0.0 только с пользователями. Тексты `localPass` и `lanAllow` в `info.ru.json` обновлены, в макете — при следующей перегенерации.

## ADR-014 · 2026-10-07 · DPAPI через пакет Microsoft
**Решение:** `System.Security.Cryptography.ProtectedData` 10.0.12 (Microsoft) для шифрования `secrets.bin` (DataProtectionScope.CurrentUser + энтропия приложения). **Почему:** официальный пакет из того же источника, что и рантайм; своя обёртка над CryptProtectData — лишний код в критичном месте.

## ADR-015 · 2026-10-07 · Наборы правил закреплены по коммиту
**Решение:** `.srs`-файлы (geosite-category-ru, geoip-ru от SagerNet; ru-blocked от runetfreedom, GPL-3.0) закреплены в `tools/geo.lock.json` ссылками на конкретный коммит raw.githubusercontent.com и SHA-256. Lock-файлы ядер и баз вшиты в `Tropa.Infrastructure` как ресурсы. Перед каждым запуском ядра хэши баз сверяются. **Почему:** ветки этих репозиториев обновляются ежедневно, ссылка на ветку дала бы неконтролируемое содержимое. **Последствия:** базы устаревают между релизами до этапа 7 (подписанный манифест с ежедневными обновлениями).

## ADR-016 · 2026-10-07 · Служба: доверие только по пути в Program Files
**Решение:** служба принимает команды только от `Tropa.exe` из своего каталога, интерфейс работает только со службой `Tropa.Service.exe` из своего каталога. Сверяются пути процессов на обоих концах канала (`GetNamedPipeClientProcessId` / `GetNamedPipeServerProcessId`). Первый экземпляр канала создаётся с `FirstPipeInstance`: если имя уже занято, служба не стартует. Клиент подключается с уровнем олицетворения Identification. **Почему:** каталог в Program Files доступен на запись только администраторам, поэтому подменить программу без прав администратора нельзя. Подпись Authenticode добавим, когда появится сертификат (этап 7). **Последствия:** при отладке интерфейс и служба лежат в разных каталогах, поэтому в Debug-сборке есть переопределения `TROPA_DEV_CLIENT` и `TROPA_DEV_SERVICE`; для полноценной проверки — `tools/dev-install.ps1`.

## ADR-017 · 2026-10-07 · Управляющий клиент и остановка при отключении
**Решение:** подключением управляет один клиент. Если он отключился (интерфейс закрыт, упал или его убили), служба останавливает ядро и откатывает свои изменения. **Почему:** подключение без интерфейса никто не сможет выключить, а TUN перехватывает весь трафик. Kill switch, которому как раз нужно «не отпускать» трафик, появится на этапе 6 как явная настройка.

## ADR-018 · 2026-10-07 · Конфиги Xray проверяются сквозными тестами
**Решение:** golden-конфиги Xray прогоняются через `xray run -test`, а ключевые сценарии (VLESS+XHTTP, Reality) — через настоящее подключение в интеграционных тестах. `XrayConfigGuard` запрещает корневой объект `env` и всё, кроме наших входов/выходов. **Почему:** Xray молча игнорирует неизвестные поля, поэтому опечатка в имени поля не ловится проверкой конфига. **Последствия:** для Reality пишем ключ и в `password` (Xray 25+), и в `publicKey` (старые версии).

## ADR-019 · 2026-10-07 · Гибрид двух ядер
**Решение:** sing-box остаётся единственной точкой входа (TUN, DNS, правила). Серверы, которым нужен Xray (XHTTP или выбор «Всегда Xray»), и UDP-шум прямого трафика уходят в локальный Xray через SOCKS-входы на 127.0.0.1 с одноразовым логином и паролем. Трафик самого xray.exe в TUN идёт напрямую (`process_path`), чтобы не было петли. Служба запускает оба ядра, проверяет хэши обоих и перезапускает оба при падении любого. **Почему:** одна таблица правил и один DNS — меньше мест для утечки; Xray добавляет только то, чего нет в sing-box. **Последствия:** протокол IPC — версия 2; цепочки через Xray-серверы пока не поддерживаются.

## ADR-020 · 2026-10-07 · Утечки проверяем без сторонних сервисов
**Решение:** шаг «Утечки» не обращается к сервисам вида dnsleaktest: он смотрит на режим, перехват DNS, политику умного разрешения имён, строгий маршрут и IPv6 на адаптерах. **Почему:** такие сервисы получают IP пользователя и уникальный поддомен — это передача данных третьей стороне, а правило 7 запрещает отправку чего-либо без явного действия. **Последствия:** проверка структурная, а не фактическая; в справке (`leaks`) так и написано.

## ADR-021 · 2026-10-07 · Kill switch на динамическом сеансе WFP
**Решение:** блокировку ставит служба через Windows Filtering Platform в сеансе с `FWPM_SESSION_FLAG_DYNAMIC`. Разрешены: ядра по пути к exe, наш TUN (по LUID, обновляется после каждого перезапуска ядра), loopback, DHCP и при обходе LAN — локальные сети; всё остальное на уровнях ALE connect/accept блокируется. Блокировка включается до запуска ядра, переживает переподключение (Start без Stop) и пропажу интерфейса, снимается командой «Отключить», «Аварийно вернуть настройки сети» или остановкой службы. **Почему:** динамические фильтры Windows удаляет сама, когда закрывается дескриптор (в том числе при падении службы), поэтому «вечной» блокировки после сбоя не бывает и журнал для них не нужен. Структуры сверены с wireguard-windows (MIT). **Последствия:** блокировка не переживает перезапуск службы и перезагрузку — это осознанный компромисс в пользу безопасности данных пользователя.

## ADR-022 · 2026-10-07 · Протокол службы, версия 3
**Решение:** `StartRequest` получил `KillSwitch`, `KillSwitchAllowLan`, `LoopbackSids`; `StatusEvent` — флаг `Blocking`; новая команда `RollbackAll`, доступная любому проверенному клиенту. Канал — `Tropa.Service.v3`. **Почему:** «красная кнопка» должна работать, даже если подключением управляет другой экземпляр интерфейса. **Последствия:** интерфейс и службу обновлять только вместе.
