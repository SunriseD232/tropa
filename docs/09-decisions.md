# 09. Журнал решений (ADR)

Формат: номер, дата, решение, почему, последствия. Новые решения — в конец.

## ADR-001 · 2026-10-07 · Безопасность данных — приоритет №1
**Решение:** при конфликте «безопаснее» против «лучше обходит» выбираем безопасность. **Почему:** требование владельца. Друзья доверяют программе компьютер и данные. **Последствия:** `02-security.md` обязателен к исполнению, у каждого PR есть чек-лист.

## ADR-002 · 2026-10-07 · Без zapret, GoodbyeDPI, WinDivert
**Решение:** не встраивать и не запускать сторонние утилиты и драйверы обхода DPI. Приёмы (фрагментация, шум) реализуем только опциями ядер sing-box/Xray. **Почему:** риск вредоноса в обновлениях, драйвер ядра с полным доступом к трафику, риск потери данных. **Последствия:** фрагментация работает только для трафика, проходящего через ядро (режим TUN или прокси), а не для всей системы на уровне драйвера.

## ADR-003 · 2026-10-07 · Ядра тоже под контролем цепочки поставок
**Решение:** закреплённые версии и SHA-256, обновление только через наш подписанный Ed25519 манифест, проверка хэша перед каждым запуском. **Почему:** ядра — такой же сторонний код, как zapret. **Последствия:** новые версии ядер появляются у пользователей после проверки владельцем, а не сразу.

## ADR-004 · 2026-10-07 · Стек: .NET 10 + Avalonia 11
**Решение:** C#/.NET 10 LTS, Avalonia (11 → обновлено до 12, см. ADR-010), CommunityToolkit.Mvvm, xUnit, Inno Setup. **Почему:** нативная работа со службами Windows, DPAPI, WFP, реестром. Avalonia даёт современный UI, встроенный трей и возможность портирования. **Альтернативы:** WPF (только Windows, устаревший вид), Tauri (сложнее работа с привилегиями и службой).

## ADR-005 · 2026-10-07 · Разделение на App (пользователь) и Service (SYSTEM)
**Решение:** привилегированные операции — только в службе Windows. Интерфейс без прав администратора. Автозапуск интерфейса через HKCU Run. **Почему:** минимальная привилегированная поверхность, нет UAC при каждом входе. **Последствия:** тексты `autostart` в `info.ru.json` и в исходниках макета исправлены (2026-10-07); холст обновится при следующей публикации.

## ADR-006 · 2026-10-07 · Конфиг ядра генерирует App, служба его проверяет
**Решение:** генерация в App (там доступны секреты DPAPI CurrentUser), повторная проверка `ConfigGuard` в службе. **Почему:** секреты не хранятся под SYSTEM, а служба не доверяет клиенту.

## ADR-007 · 2026-10-07 · sing-box основное ядро, Xray по требованию
**Решение:** sing-box всегда фронт (TUN, DNS, правила по процессам). Xray запускается за SOCKS только для XHTTP и Xray-only функций. **Почему:** у sing-box лучше TUN и правила по процессам, у Xray новинки протокола. **Последствия:** UDP для гибридных профилей идёт через SOCKS5 UDP ASSOCIATE, его надо проверить интеграционными тестами.

## ADR-008 · 2026-10-07 · Сторонние конфиги не исполняются
**Решение:** из импортируемых JSON берём только outbound-ы. Пользовательский шаблон сливается по белому списку. **Почему:** чужой конфиг может писать файлы (`log.output`), открывать порты наружу, уводить трафик.

## ADR-009 · 2026-10-07 · Нет своей серверной части
**Решение:** клиент работает со сторонними подписками. Важна совместимость: User-Agent, HWID, разные форматы ответа. **Почему:** друзья используют чужие подписки.

## ADR-010 · 2026-10-07 · Актуальные версии на старте
**Решение:** Avalonia 12.1.3 (а не 11, как в первой версии ADR-004), CommunityToolkit.Mvvm 8.4.2, xUnit v3 3.2.2 (стабильная линия 3.x вместо свежей 4.0), Microsoft.Extensions.Hosting.WindowsServices 10.0.12. Ядра: sing-box 1.14.2, Xray 26.9.30. **Почему:** последние стабильные версии на дату старта. **Последствия:** примеры конфигов в `05-config-generation.md` писались для sing-box 1.12. Каждый блок генератора сверяется со схемой 1.14 и фиксируется golden-тестом.

## ADR-011 · 2026-10-07 · Лицензии ядер
**Решение:** sing-box — GPL-3.0-or-later, Xray — MPL-2.0. Распространяем их неизменёнными бинарниками отдельными процессами. В установщик кладём тексты лицензий и ссылки на исходники точных версий (тег из lock-файла). **Почему:** требования GPL/MPL при распространении бинарников. **Последствия:** своё приложение не линкуется с ядрами и общается с ними только через конфиги и процессы.

## ADR-012 · 2026-10-07 · CI закреплён по хэшам
**Решение:** GitHub Actions подключаются по SHA коммита (`actions/checkout` v7.0.1, `actions/setup-dotnet` v6.0.0), у токена только `contents: read`, restore в `--locked-mode`. **Почему:** тег action можно перевесить на вредоносный коммит. Это та же угроза цепочки поставок, что и с ядрами.

## ADR-013 · 2026-10-07 · Отдельный порт для локальной сети
**Решение:** локальный mixed-порт всегда слушает только 127.0.0.1. В режиме «Только браузеры» он без пароля: системный прокси Windows не умеет передавать учётные данные, и браузеры показывали бы окно ввода пароля. Доступ из LAN — отдельный inbound `lan-in` на `LanPort` (10809), пароль на нём обязателен всегда. **Почему:** нельзя одновременно иметь системный прокси без запроса пароля и защищённый порт, открытый в сеть. **Последствия:** правило совместимости «LAN → пароль на локальном порту» заменено на «Только браузеры → без пароля на локальном порту»; `ConfigGuard` пропускает 0.0.0.0 только с пользователями. Тексты `localPass` и `lanAllow` в `info.ru.json` обновлены, в макете — при следующей перегенерации.

## ADR-014 · 2026-10-07 · DPAPI через пакет Microsoft
**Решение:** `System.Security.Cryptography.ProtectedData` 10.0.12 (Microsoft) для шифрования `secrets.bin` (DataProtectionScope.CurrentUser + энтропия приложения). **Почему:** официальный пакет из того же источника, что и рантайм; своя обёртка над CryptProtectData — лишний код в критичном месте.

## ADR-015 · 2026-10-07 · Наборы правил закреплены по коммиту
**Решение:** `.srs`-файлы (geosite-category-ru, geoip-ru от SagerNet; ru-blocked от runetfreedom, GPL-3.0) закреплены в `tools/geo.lock.json` ссылками на конкретный коммит raw.githubusercontent.com и SHA-256. Lock-файлы ядер и баз вшиты в `Tropa.Infrastructure` как ресурсы. Перед каждым запуском ядра хэши баз сверяются. **Почему:** ветки этих репозиториев обновляются ежедневно, ссылка на ветку дала бы неконтролируемое содержимое. **Последствия:** базы устаревают между релизами до этапа 7 (подписанный манифест с ежедневными обновлениями).

## ADR-016 · 2026-10-07 · Служба: доверие только по пути в Program Files
**Решение:** служба принимает команды только от `Tropa.exe` из своего каталога, интерфейс работает только со службой `Tropa.Service.exe` из своего каталога. Сверяются пути процессов на обоих концах канала (`GetNamedPipeClientProcessId` / `GetNamedPipeServerProcessId`). Первый экземпляр канала создаётся с `FirstPipeInstance`: если имя уже занято, служба не стартует. Клиент подключается с уровнем олицетворения Identification. **Почему:** каталог в Program Files доступен на запись только администраторам, поэтому подменить программу без прав администратора нельзя. Подпись Authenticode добавим, когда появится сертификат (этап 7). **Последствия:** при отладке интерфейс и служба лежат в разных каталогах, поэтому в Debug-сборке есть переопределения `TROPA_DEV_CLIENT` и `TROPA_DEV_SERVICE`; для полноценной проверки — `tools/dev-install.ps1`.

## ADR-017 · 2026-10-07 · Управляющий клиент и остановка при отключении
**Решение:** подключением управляет один клиент. Если он отключился (интерфейс закрыт, упал или его убили), служба останавливает ядро и откатывает свои изменения. **Почему:** подключение без интерфейса никто не сможет выключить, а TUN перехватывает весь трафик. Kill switch, которому как раз нужно «не отпускать» трафик, появится на этапе 6 как явная настройка.

## ADR-018 · 2026-10-07 · Конфиги Xray проверяются сквозными тестами
**Решение:** golden-конфиги Xray прогоняются через `xray run -test`, а ключевые сценарии (VLESS+XHTTP, Reality) — через настоящее подключение в интеграционных тестах. `XrayConfigGuard` запрещает корневой объект `env` и всё, кроме наших входов/выходов. **Почему:** Xray молча игнорирует неизвестные поля, поэтому опечатка в имени поля не ловится проверкой конфига. **Последствия:** для Reality пишем ключ и в `password` (Xray 25+), и в `publicKey` (старые версии).

## ADR-019 · 2026-10-07 · Гибрид двух ядер
**Решение:** sing-box остаётся единственной точкой входа (TUN, DNS, правила). Серверы, которым нужен Xray (XHTTP или выбор «Всегда Xray»), и UDP-шум прямого трафика уходят в локальный Xray через SOCKS-входы на 127.0.0.1 с одноразовым логином и паролем. Трафик самого xray.exe в TUN идёт напрямую (`process_path`), чтобы не было петли. Служба запускает оба ядра, проверяет хэши обоих и перезапускает оба при падении любого. **Почему:** одна таблица правил и один DNS — меньше мест для утечки; Xray добавляет только то, чего нет в sing-box. **Последствия:** протокол IPC — версия 2; цепочки через Xray-серверы пока не поддерживаются.

## ADR-020 · 2026-10-07 · Утечки проверяем без сторонних сервисов
**Решение:** шаг «Утечки» не обращается к сервисам вида dnsleaktest: он смотрит на режим, перехват DNS, политику умного разрешения имён, строгий маршрут и IPv6 на адаптерах. **Почему:** такие сервисы получают IP пользователя и уникальный поддомен — это передача данных третьей стороне, а правило 7 запрещает отправку чего-либо без явного действия. **Последствия:** проверка структурная, а не фактическая; в справке (`leaks`) так и написано.

## ADR-021 · 2026-10-07 · Kill switch на динамическом сеансе WFP
**Решение:** блокировку ставит служба через Windows Filtering Platform в сеансе с `FWPM_SESSION_FLAG_DYNAMIC`. Разрешены: ядра по пути к exe, наш TUN (по LUID, обновляется после каждого перезапуска ядра), loopback, DHCP и при обходе LAN — локальные сети; всё остальное на уровнях ALE connect/accept блокируется. Блокировка включается до запуска ядра, переживает переподключение (Start без Stop) и пропажу интерфейса, снимается командой «Отключить», «Аварийно вернуть настройки сети» или остановкой службы. **Почему:** динамические фильтры Windows удаляет сама, когда закрывается дескриптор (в том числе при падении службы), поэтому «вечной» блокировки после сбоя не бывает и журнал для них не нужен. Структуры сверены с wireguard-windows (MIT). **Последствия:** блокировка не переживает перезапуск службы и перезагрузку — это осознанный компромисс в пользу безопасности данных пользователя.

## ADR-022 · 2026-10-07 · Протокол службы, версия 3
**Решение:** `StartRequest` получил `KillSwitch`, `KillSwitchAllowLan`, `LoopbackSids`; `StatusEvent` — флаг `Blocking`; новая команда `RollbackAll`, доступная любому проверенному клиенту. Канал — `Tropa.Service.v3`. **Почему:** «красная кнопка» должна работать, даже если подключением управляет другой экземпляр интерфейса. **Последствия:** интерфейс и службу обновлять только вместе.

## ADR-023 · 2026-10-07 · Обновления через подписанный манифест (ECDSA P-256)
**Решение:** манифест (`schema`, `sequence`, `issued`, `expires`, `app`, `cores` и `geo` в форматах lock-файлов) подписывается ECDSA P-256 + SHA-256, подпись IEEE P1363 лежит рядом (`manifest.json.sig`, base64). Публичный ключ, адрес манифеста и номер выпуска установщика вшиты в сборку (`tools/update.config.json`). Интерфейс скачивает манифест, проверяет подпись, номер (не меньше уже виденного и установленного) и срок, качает только изменившиеся архивы и наборы правил, сверяет хэши архива и извлечённого файла. Служба получает каталог с файлами и манифест, **заново** проверяет подпись и номер, копирует каждый файл со сверкой хэша в `%ProgramData%\Tropa\updates\<номер>` и запускает ядра оттуда со списками из манифеста. Сама служба ничего не качает и не распаковывает. Установщик новой версии скачивается только из `github.com/.../releases/download/...`, сверяется по SHA-256 из манифеста и запускается кнопкой. **Почему не Ed25519, как планировали:** в .NET 10 его нет, а альтернатива — сторонняя криптобиблиотека или своя реализация; ECDSA P-256 встроена в Windows CNG и так же надёжна для подписи. **Последствия:** закрытый ключ хранится у владельца, зашифрованный паролем; потеря ключа = ручная переустановка у всех. Манифест нужно перевыпускать раньше срока (90 дней).

## ADR-024 · 2026-10-07 · Установщик
**Решение:** Inno Setup, только `Program Files\Tropa` (каталог выбрать нельзя: на этом построено доверие службы, ADR-016), самодостаточная сборка win-x64 (друзьям не нужен .NET). Перед установкой — аварийный откат прежней версии и удаление её службы; служба ставится `Tropa.Service.exe --install`. Автозапуск пишет сама Тропа от имени пользователя (`--set-autostart=on|off`, задача установщика); значение в HKCU\…\Run содержит путь к нашему exe, чужое значение с тем же именем не трогаем. Удаление: `Tropa.exe --emergency-rollback`, удаление автозапуска, `Tropa.Service.exe --uninstall` (откат DNS-политики и loopback-исключений), удаление `%ProgramData%\Tropa`; настройки и подписки — только по согласию. В «Пуске» есть «Аварийно вернуть настройки сети».

## ADR-025 · 2026-10-07 · Подпись кода отложена
**Решение:** установщик и программа пока не подписаны Authenticode. **Почему:** бесплатный путь (SignPath Foundation) требует публичного репозитория, платный — сертификата с аппаратным ключом; выбор за владельцем. **Последствия:** SmartScreen предупреждает при первом запуске; служба доверяет программе по пути в Program Files (ADR-016), обновления защищены подписью манифеста, так что их безопасность от Authenticode не зависит.

## ADR-026 · 2026-10-07 · Shadowsocks-2022 и Hysteria2
**Решение:** поддерживаются ссылки `ss://` (SIP002 и старый base64-формат) и `hysteria2://` / `hy2://`. Shadowsocks — только методы 2022 и AEAD; потоковые шифры, `none` и плагины отклоняются: они либо небезопасны, либо требуют запуска сторонних программ. Для методов 2022 проверяется длина ключа. Hysteria2 — всегда TLS, маскировка Salamander (пароль хранится в DPAPI, как и основной), без uTLS (у QUIC его нет) и без Mux; диапазон портов не используется (берётся первый). Hysteria2 работает только в sing-box, даже при «Всегда Xray»; Shadowsocks — в обоих ядрах. TCP-пинг для Hysteria2 пропускается: у QUIC нет TCP-порта. **Почему:** оба протокола часто встречаются в российских подписках, а sing-box поддерживает их без сторонних компонентов.

## ADR-027 · 2026-10-07 · Что отложено на этапе 8
**Решение:** не делаем сейчас: английский интерфейс (все строки на русском прямо в разметке — перевод потребует вынести их в ресурсы), Clash YAML (нужна библиотека YAML, а панели отдают нашему User-Agent обычные ссылки), уведомления Windows (для приложения без пакета MSIX нужен ярлык с AppUserModelID — сделаем вместе с подписью кода), свой шаблон конфига и domainStrategy/routeOnly (влияют на безопасность и маршрутизацию, требуют отдельной проверки). В настройках их нет, чтобы не показывать пункты, которые ничего не делают.

## ADR-028 · 2026-10-07 · Настройки и тема
**Решение:** экран настроек строится из описаний строк (переключатель, выбор, текст, число, действие); для каждой — ключ справки и ключ CompatRules. Ввод проверяется `SettingsValidation` (те же правила при импорте файла). Ручная правка приёмов обхода DPI переводит набор в «Свои». Тема — словари ресурсов Avalonia по ThemeVariant, поэтому смена мгновенная, а «как в Windows» следует системе.

## ADR-029 · 2026-10-07 · Сначала обход DPI, сервер — подстраховка
**Решение:** при включённом режиме группы YouTube, Discord, Telegram и «остальное заблокированное» (наборы runetfreedom) идут через переключатели sing-box (`selector`) с выбором «dpi-direct» (напрямую, фрагментация TLS из правила, адреса через удалённый DNS — провайдерский их подменяет) или «proxy». Тропа сразу после подключения и затем раз в 3 минуты проверяет каждую группу запросом через отдельный вход `probe-dpi` (127.0.0.1, пароль), маршрут которого — тот же «dpi-direct» с фрагментацией, и переключает группу через Clash API без переподключения. Явные правила пользователя и ИИ-сервисы (всегда через сервер) стоят раньше групп. **Почему:** встроенная проверка задержки Clash API не применяет фрагментацию из правил (идёт мимо маршрутизатора), поэтому проверять нужно ровно тем путём, которым пойдёт трафик. **Последствия:** проверка — по одному адресу на группу; если у сервиса открывается главная, но не работает, например, видео, нужно правило «через сервер». UDP-шум в этом режиме не используется.

## ADR-030 · 2026-10-07 · Своё ядро у каждого сервера
**Решение:** у сервера хранится выбор пользователя (Автоматически / sing-box / Xray) и найденное проверкой ядро. «Автоматически»: тест сначала через Xray, неработающие — повторно через sing-box; найденное ядро запоминается и используется в плане ядер (CorePlan). При подключении к серверу с неизвестным ядром Тропа быстро проверяет его тем же способом (не удалось — подключается по общей настройке). XHTTP — только Xray, Hysteria2 — только sing-box. **Почему:** у владельца рабочие на Xray серверы не работали в sing-box, а общая настройка этого не учитывала.

## ADR-031 · 2026-10-07 · Наборы правил runetfreedom
**Решение:** все наборы — из runetfreedom/russia-v2ray-rules-dat (официальный источник гео-баз v2rayN), закреплены по коммиту и SHA-256: category-ru, category-gov-ru, category-bank-ru, ru-available-only-inside, geoip-ru (напрямую); ru-blocked, geoip-ru-blocked, geoip-ru-blocked-community (заблокированное); category-ai-!cn (ИИ-сервисы, закрытые для России, — всегда через сервер); youtube, discord, telegram, geoip-telegram (группы обхода DPI). ru-blocked-all (≈700 тыс. доменов) не берём: авторы сами советуют осторожность. Обновляются подписанным манифестом.


## ADR-032 · 2026-10-08 · Правила по IP-спискам: сначала узнать адрес
**Решение:** перед правилами по IP-наборам (geoip-ru-blocked, geoip-ru-blocked-community, geoip-ru, IP-части групп «сначала обход DPI» и пользовательские правила с IP/geoip) в маршрут ставится действие sing-box `resolve`. Порядок: все правила по доменам → `resolve` → правила по IP. Сервер DNS для `resolve`: «remote» (через сервер), если без совпадения трафик ушёл бы на сервер («Всё, кроме российского», «Всё через сервер»); «local» — если ушёл бы напрямую («Только заблокированное», обход без сервера). **Почему:** при FakeIP, системном прокси и определении домена соединение несёт только имя, а IP-правила в sing-box 1.11+ сами адрес не узнают — они не срабатывали никогда (проверено на sing-box 1.14.2: без `resolve` правило `ip_cidr 0.0.0.0/0` не совпадает с соединением к ya.ru, с `resolve` — совпадает). Из-за этого, например, static.licdn.com (картинки и скрипты LinkedIn) есть только в geoip-ru-blocked и шёл напрямую. `resolve` заполняет адреса, но имя назначения сохраняет — сервер по-прежнему получает домен. «remote» выбран ради приватности: иначе провайдерский DNS видел бы все сайты, которые идут через сервер. **Последствия:** первое соединение к новому домену ждёт один DNS-запрос (дальше кэш).

## ADR-033 · 2026-10-08 · Кнопка «Обход DPI» и обход без сервера
**Решение:** на главной отдельная большая кнопка `Dpi.Bypass` (сохраняется, работает с запуска Тропы). Не подключено к серверу → движок запускает ядро «только обход» (`SingBoxInput.Active = null`): в маршруте нет выхода «proxy»; ru-blocked, youtube, discord, telegram идут через `dpi-direct` (адреса через удалённый DNS напрямую по DoH — провайдерский их подменяет) с `tls_fragment`; QUIC (UDP 443) для этих наборов отклоняется, чтобы браузер перешёл на TCP; правила «через сервер» трактуются как «напрямую с обходом»; DNS final — локальный. Подключено → кнопка принудительно включает фрагментацию прямого трафика (CompatRules: `fragment`). «Подключить» заменяет ядро обхода подключением, «Отключить» возвращает ядро обхода; через службу — одной командой Start, без промежутка. **Почему:** у друзей не открывается LinkedIn (его режет ТСПУ по SNI), а VPN для этого включать не хотят. Сторонние драйверы (zapret, GoodbyeDPI) запрещены правилом 2 — только средства ядра. **Последствия:** сайты, закрытые по IP, и сервисы, не пускающие пользователей из России, без сервера не откроются (сказано в справке). Kill switch в режиме без сервера не используется.

## ADR-034 · 2026-10-08 · Постоянное имя адаптера TUN
**Решение:** TUN называется «Tropa» (`interface_name`). Адаптер с этим именем не считается «другим VPN» и не меняет «подпись сети» для переподключения. **Почему:** при «Применить сейчас» ядро перезапускается; адаптер «tun0» с описанием «sing-tun Tunnel» мог появиться раньше, чем получал адрес 172.19.0.1, и Тропа предупреждала о втором VPN — то есть о себе. С постоянным именем sing-tun ещё и переиспользует тот же адаптер вместо нового.

## ADR-035 · 2026-10-09 · Обход DPI — через Xray, мелкими кусками
**Решение:** весь трафик «напрямую с обходом» (`dpi-direct`: группы «сначала обход», обход без сервера, «всем прямым HTTPS», проверки групп) идёт в sing-box через SOCKS-выход во вход Xray `direct-in`; там `freedom` с `fragment` (по умолчанию `tlshello`, 1–5 байт, пауза 1–3 мс) и своим DNS (удалённый DoH из настроек, `UseIPv4`). Xray запускается, когда включена фрагментация или шум. `tls_fragment` sing-box остаётся только запасным путём, если входа Xray нет. Кнопка «Обход DPI» при подключении принудительно включает «Сначала обход DPI» (ADR-029) во всех пресетах, в том числе «Всё через сервер». Сохранённые старые значения по умолчанию (100-200 / 10-20, набор не «Свои») при запуске заменяются новыми. В проверке конфига Xray разрешён раздел `dns` (только `servers` — IP или https:// — и `queryStrategy`). **Почему:** проверка у провайдера владельца в РФ (2026-10-09, мимо туннеля, 15 сайтов): `tls_fragment` и `tls_record_fragment` sing-box не открыли ни одного сайта; Xray 1-5/1-3 — YouTube (и googlevideo), Facebook, BBC стабильно, Discord через раз; 100-200/10-20 — почти ничего. LinkedIn режут по SNI (тот же IP Cloudflare с другим SNI отвечает), но ни один из 13 вариантов фрагментации и ни domain fronting (Cloudflare отвечает 403) его не открыли; X, Instagram, Telegram, rutracker — тоже нет. Для них остаётся сервер — «сначала обход» сам переключает группу на сервер по проверке. **Последствия:** Xray работает почти всегда, когда включён обход; через SOCKS к Xray идёт и UDP группы «напрямую с обходом» (без шума — как обычный прямой). Группа «остальное заблокированное» проверяется адресом rutracker (закрыт по IP), поэтому при подключении она по-прежнему почти всегда идёт через сервер — переключать её по сайту, который обход открывает, нельзя: тогда закрытые по IP сайты группы перестали бы открываться.

## ADR-036 · 2026-10-09 · Группы обхода помельче и подбор параметров
**Решение:** (1) Группы «сначала обход DPI» разбиты по сервисам: YouTube, Discord, Telegram, Facebook, Instagram, X (Twitter), «остальное заблокированное». Facebook и Instagram — отдельные группы (их домены и CDN в наборах runetfreedom не пересекаются: fbcdn у facebook, cdninstagram у instagram), поэтому Facebook идёт напрямую с обходом, даже если Instagram у провайдера так не открывается. У каждой группы свой переключатель и своя проверка; общий список блокировок проверяется по rutracker (закрыт по IP) и обычно уходит на сервер. Добавлены наборы geosite-facebook, geosite-instagram, geosite-x (geosite-x включает и twitter.com) — закреплены по тому же коммиту runetfreedom и SHA-256; эти же наборы добавлены в BypassDomains (DNS и блок QUIC для режима без сервера). (2) Кнопка «Подобрать» (`TuneDpiAsync`/`ServerTester.TuneFragmentAsync`): перебирает `DpiSettings.TuningVariants` (6 вариантов фрагментации), для каждого поднимает одиночное ядро Xray «напрямую» на физическом адаптере (мимо туннеля, как тесты серверов) и проверяет YouTube и Discord; сохраняет вариант, открывший больше всего (набор → «Свои»), и применяет сразу. Останавливается, как только вариант открыл оба адреса. Конфиг подбора проходит ту же проверку XrayConfigGuard; привязка к адаптеру — через `streamSettings.sockopt.interface` (в обычной работе маршрут Xray задаёт sing-box, привязка не используется). **Почему:** у разных провайдеров работают разные настройки обхода (как десятки «стратегий» ALT в zapret-сборках); ручной перебор неудобен. Проверено вживую у владельца в РФ: подбор нашёл рабочий вариант, при живой проверке вариант 1-2/1-2 открывал и YouTube, и Discord. Разбиение групп даёт больше сайтов напрямую: Facebook не тянется на сервер из-за rutracker. **Последствия:** групп теперь 7, проверка каждые 3 минуты перебирает все (последовательно, до ~1 минуты в худшем случае). Подбор запускает до 6 временных ядер Xray подряд; текущее подключение не трогается. Драйверы и приёмы zapret (поддельные пакеты, WinDivert) по-прежнему не используются — только встроенная фрагментация ядра (правило 2).
