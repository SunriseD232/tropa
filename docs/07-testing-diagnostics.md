# 07. Тесты серверов и диагностика

## 1. Тесты серверов

Каждый тест служба выполняет во **временном экземпляре ядра**: отдельный процесс и отдельный конфиг, в котором у каждого тестируемого сервера свой SOCKS-inbound на `127.0.0.1:<случайный порт>` с авторизацией. Текущее подключение не трогается. Параллельность — настройка `parallel`. Временные экземпляры убиваются по таймауту 60 с.

| Тест | Алгоритм | Таймаут | Результат |
|---|---|---|---|
| TCP-пинг | `Socket.ConnectAsync` к адресу:порту сервера напрямую, 3 попытки, медиана | 3 с | мс / нет ответа |
| Реальная задержка | GET `testUrl` через SOCKS сервера. Первый запрос прогревочный, затем 2 замера, берётся минимум | 5 с | мс / ошибка (с типом: TLS, auth, timeout) |
| Скорость | GET `speedUrl` (`speedSize` МБ) через SOCKS. Замер байт/с по скользящему окну 1 с | 20 с | Мбит/с; см. «заморозку» ниже |
| UDP | STUN Binding Request (RFC 5389) к `stunServer` через SOCKS5 UDP ASSOCIATE | 3 с | работает / нет |
| Стабильность | 30 запросов реальной задержки раз в секунду | 35 с | потери %, джиттер (стандартное отклонение), медиана |

### Детектор «заморозки»
При скачивании: если получено > 0 и < 64 КБ, а затем 8 секунд нет новых данных, статус **«Данные не идут»** с пояснением «похоже на ограничение IP хостинга». Это отдельный статус, не «нет ответа»: подсказки пользователю разные.

### Статус сервера
- **Нет ответа** — TCP-пинг не прошёл.
- **Ошибка рукопожатия** — TCP есть, реальная задержка падает на TLS/Reality.
- **Данные не идут** — сработал детектор заморозки.
- **Медленно** — задержка > 150 мс или скорость < 5 Мбит/с.
- **Работает** — во всех остальных случаях.

### Авто-выбор
- urltest-группа sing-box: быстрые переключения по задержке.
- Служба раз в `autoInterval` × 10 (не чаще раза в 30 мин) делает тест скорости малым объёмом (1 МБ) активного и двух лучших резервных серверов. «Замёрзшие» исключаются из группы на 1 час (перегенерация конфига).
- Допуск `autoTol` обязателен, чтобы не прыгать между близкими серверами.

## 2. Диагностика (по шагам)

| # | Шаг (ключ справки) | Как проверяем | Вывод пользователю |
|---|---|---|---|
| 1 | Интернет без прокси (`netDirect`) | GET https://ya.ru напрямую, мимо ядра (bind на физический интерфейс) | нет сети / капча провайдера / работает |
| 2 | Часы (`clock`) | Заголовок `Date` из шага 1 против системного времени | расхождение, совет включить синхронизацию |
| 3 | Сервер отвечает (`tcping`) | TCP-пинг активного сервера | — |
| 4 | Рукопожатие (`realityHs`) | реальная задержка; ошибку из лога ядра классифицируем | неверный ключ / SNI / сеть |
| 5 | Данные идут (`dataFlow`) | тест скорости 10 МБ с детектором заморозки | — |
| 6 | Подмена DNS (`dnsPoison`) | A-запрос к DNS провайдера (системный) и через туннель для discord.com, youtube.com, x.com; сравнение со списком известных заглушек и между собой | подменяет / нет; работает ли обход |
| 7 | UDP (`udpTest`) | STUN через активный сервер | голос будет / не будет работать |
| 8 | Утечки (`leaks`) | DNS: запрос к уникальному поддомену сервиса проверки утечек и сравнение резолвера. IPv6: попытка соединения с IPv6-адресом мимо туннеля | — |
| 9 | Другой VPN (`otherVpn`) | `GetAdaptersAddresses`: активные адаптеры с описанием WireGuard/OpenVPN/TAP/Outline/и т. п. и маршрут по умолчанию не через наш TUN | какой адаптер и как отключить |

Каждый шаг возвращает `{status: ok|warn|bad, title, details, action?}`. Шаги независимы: падение одного не останавливает остальные.

## 3. Отчёт
Текстовый (Markdown) файл: версии Тропы, ядер и Windows; режим; пресет; список правил (без секретов); результаты шагов; последние 200 строк журнала. Всё проходит через `SecretScrubber`. Адреса серверов заменяются на `server-1…N` (таблица соответствия остаётся только у пользователя). Перед сохранением показывается предпросмотр.

## 4. Автотесты проекта

- `Tropa.Core.Tests`: парсеры (корпус), подписки (base64 варианты, заголовки), CompatRules (все строки таблиц из `04-domain-model.md`), генераторы (golden), SecretScrubber, NameSanitizer, ConfigGuard (вредоносные конфиги из `Corpus/malicious/`).

- Ручной чек-лист перед релизом: TUN на чистой Windows 10 и 11, откат после убийства службы, удаление программы без следов.
